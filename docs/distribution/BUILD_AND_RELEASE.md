# Windows/macOS distribution inputs

Target Forge license: GPL-3.0-or-later, subject to exact dependency and corresponding-source review. `LICENSE_STATUS.md` and the reader lock remain pending. No script writes an approval, supplies credentials, or publishes a catalog. Internal installers are NON_REDISTRIBUTABLE and confer no supported-platform claim.

## Build matching source

Use the exact commit in `inventory.json`, an existing Java 17 JDK of the target architecture, Node and pnpm, the committed Gradle wrapper, and both committed pnpm locks. Windows x64 and macOS x64/arm64 require separate native builds. Do not modify the release checkout after inventory creation. Keep output under ignored `build/`.

1. `pnpm --dir desktop install --frozen-lockfile`
2. Run `gradlew test distributionInventory --no-configuration-cache -Ppathlab.forge.viewer.defaultOrigin=https://OFFICIAL_VIEWER_ORIGIN -Ppathlab.forge.readerRuntimeRoot=OWNER_APPROVED_RUNTIME -Ppathlab.forge.distributionChannel=INTERNAL` using Java 17. Replace the descriptive arguments with the existing authorized values; they are not release approval.
3. `pnpm --dir frontend test`; `pnpm --dir desktop test`; `pnpm --dir desktop check`; run the native `scripts/verify-repo.ps1` or `.sh`.
4. `pnpm --dir desktop make` creates an internal unsigned installer using the staged service. Never upload it as a release.

`distributionDependencies` emits all resolved runtime JAR coordinates, hashes and embedded legal text. `distributionInventory` emits the exact staged service bytes, SHA-256 lock inputs, installed npm metadata and legal text, notice discovery and a `git archive` of the clean commit. Legal discovery is incomplete when upstream archives omit notices; review must obtain them. The project source archive alone is not full corresponding source for bundled third-party binaries: reviewer supplies exact third-party source, patches, build scripts and installation information as required. No private slides, databases, credentials, runtime bundle or ignored files enter the Git archive.

## Production gate

Restage with `PRODUCTION` and `-Ppathlab.forge.featureCatalogPublicKey=APPROVED_ED25519_SPKI_BASE64` only after runtime lock review. The real pinned public key is required; this document supplies none. Recreate inventory from the clean commit. Review inputs in `build/distribution-inputs/review.json` must have schema `pathlab.forge.distribution-review/1`, exact `commit`, `target`, `inventorySha256`, `sourceSha256`, applicationLicense `GPL-3.0-or-later`, named `reviewer`, and `decision: APPROVED`. Every staged file hash needs a `components` entry with a reviewed license and decision; group repeated licenses in the review tooling, not by skipping binaries. `notices`, `correspondingSource`, `buildInstructions`, `licenseText` each contain a relative `file` and SHA-256; files must reside inside the input directory. The source/build instruction/legal bundles must cover the exact final build, not a general upstream URL. Inventory hashes bind them to the reviewed inputs. Human review is a required trust boundary; the JSON validator cannot establish legal rights by itself.

Set `PATHLAB_FORGE_RELEASE_INPUT` to that input directory. Windows uses the existing trusted certificate in the current user's certificate store/HSM: set public `PATHLAB_FORGE_WINDOWS_CERT_SHA1` and `PATHLAB_FORGE_TIMESTAMP_URL` (HTTPS RFC3161). SHA-256 signing and timestamping cover the packaged binaries and Squirrel full installer; no PFX password enters command arguments. macOS uses installed Developer ID Application identity `PATHLAB_FORGE_MAC_IDENTITY` and preconfigured `PATHLAB_FORGE_NOTARY_PROFILE`. Forge signs nested binaries with hardened runtime and notarizes/staples the app; postMake submits and staples the DMG using the same keychain profile. Neither debug credential logging nor private-key import is part of this workflow. No signing identity is presently evidenced, and no Mac host qualification is implied.

## Final artifact and authenticated catalog

After make, run `node scripts/verify-distribution-signatures.cjs inventory.json FINAL_INSTALLER PACKAGED_APP signature.json` on the native host. Windows verifies the final installer and every EXE/DLL/native Node binary against the trusted signer and timestamp. macOS verifies nested signatures, pinned Developer ID/timestamp, Gatekeeper and app/DMG stapled tickets. Failure produces no PASS receipt.

An independent native acceptance receipt must name exact `commit`, `version`, `target`, `artifactSha256`, `result: PASS`, `platforms` (Windows 10 22H2 and Windows 11, or macOS 14 on the named architecture), and set `dataPreserved`, `upgradeRollback`, `accessibility`, `journeys` true only from actual recorded tests. Include evidence for the active-plan journeys, clean machine startup, low-resource/process-tree measurements, NVDA/VoiceOver, keyboard/scaling, ten mixed slides, durable cancel/restart/disk-full, uncached offline use, tamper/wrong-architecture rejection, and user data preservation during upgrade/uninstall/rollback. The data root stays outside versioned installation directories; Squirrel lifecycle only changes shortcuts. Copying an older app may require a compatible data-schema backup; never delete data to make rollback pass.

Prepare a local catalog input with schema `pathlab.forge.release/1`, `commit`, `version`, `target` (`win32-x64`, `darwin-x64`, `darwin-arm64`), `channel` (`candidate` for rc.N, otherwise `stable`), `inventorySha256`, `sourceSha256`, `artifact: {file,sha256,bytes}`, `nativeAcceptance: {file,sha256}`, `signatureVerification: {file,sha256}`. Run `node scripts/distribution.cjs validate INPUT_DIRECTORY CATALOG_JSON`. It rejects absent/tampered/mismatched input and incomplete native evidence. Reviewer approval and receipt files are local private inputs, not checked-in examples or invented PASS evidence. Viewer owns authenticated immutable storage/catalog publication, range responses and permissions; accepted input is passed to that separate workflow. No background updater or unsigned download fallback is added.
